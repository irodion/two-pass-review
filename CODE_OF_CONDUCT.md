# Code of Conduct

## The short version

Be decent to people. Argue with the code, not the person who wrote it.

## What we expect

This project is a code review tool, so it attracts a particular hazard: the whole point of the work is
finding fault, and it is easy for a habit of criticising code to become a habit of criticising people.
The rubrics this project ships are deliberately harsh about implementations and explicitly not rude about
authors. Hold yourself to the same line.

In practice:

- **Critique the work.** "This adds a branch to an already tangled flow" is useful. "This is amateur
  work" is not, and says nothing the first sentence did not.
- **Assume competence.** Someone who made a choice you disagree with usually had a reason. Ask what it
  was before explaining why it was wrong.
- **Accept a decision once it is made.** Disagreeing, saying so clearly, and then getting on with it is
  a complete and respectable sequence.
- **Be welcoming.** Different experience levels, backgrounds, and native languages are not something to
  be tolerated. Assume the person asking an obvious question is the reason to write better docs.

## What is not acceptable

- Harassment, intimidation, or personal attacks, in the open or in private.
- Demeaning, insulting, or derogatory comments — including ones dressed up as technical feedback.
- Discrimination or slurs relating to age, disability, ethnicity, gender identity or expression,
  nationality, personal appearance, race, religion, or sexual identity or orientation.
- Sexual language or imagery, and unwelcome sexual attention of any kind.
- Publishing someone's private information without their explicit permission.
- Sustained disruption of discussions, or repeatedly pressing a point after a decision has been made.

## Scope

This applies anywhere the project is happening — issues, pull requests, commit messages, code comments,
and any space where someone is representing the project.

## Reporting

Report a problem to **9167139+irodion@users.noreply.github.com**. Reports are handled privately and the
reporter's identity is not shared with the person reported.

Maintainers will respond, and may edit or remove contributions, or block someone from the project, where
that is what the situation calls for. Maintainers are held to this document too — more so, not less.
