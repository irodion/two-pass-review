sec-2

Do not trust the drive root that wslpath hands back

Security & correctnesshigh
.agents/skills/two-pass-review/scripts/render.py:118-141

Corroborated by qa-2 — “The Windows path is derived and consumed in the same breath”

The WSL branch asks wslpath where the Windows drives are mounted and then joins the report's filename onto whatever comes back. wslpath reads /etc/wsl.conf, which is writable by anyone with root on the distribution and is not a value this script derived. A crafted root containing a .. sequence, or an absolute path pointing elsewhere, redirects the write outside the run directory before explorer.exe is ever invoked.

The fix is small: resolve the joined path and refuse it unless it is still inside the run's temporary directory. Do this before the file is written, not before it is opened — the opener is not the boundary.

qa-2

The Windows path is derived and consumed in the same breath

Code qualityboundary-contract
.agents/skills/two-pass-review/scripts/render.py:118-141

Corroborated by sec-2 — “Do not trust the drive root that wslpath hands back”

wslpath's answer becomes a write target with nothing in between. There is no point in the function where the derived path is a value that has been checked — it is produced by a subprocess and consumed by a join on the next line, so any reader asking "what makes this path safe?" has nowhere to look. Give the derivation a boundary that returns either a path inside the run directory or nothing, and the security argument becomes something the type of the return value carries rather than something the reader has to reconstruct.

sec-1

Compare pass provenance before formatting its display label

Security & correctnessmedium
.agents/skills/two-pass-review/scripts/page.py:242-249

Corroborated by qa-1 — “Compare the structured tier fields before formatting them”

render_scope determines whether the passes were peers from the formatted requested_tier() strings, but that rendering is not a one-to-one representation of (requested_model, requested_effort). A pass with requested_model: "high effort" and no effort, and another with no model and requested_effort: "high", both render as high effort; the page therefore claims one shared tier and suppresses the unequal-pass warning. This makes the report's provenance and corroboration warning incorrect for an accepted artifact. Compare the two structured field values, including absence, and only format them after agreement has been decided.

qa-1

Compare the structured tier fields before formatting them

Code qualityboundary-contract
.agents/skills/two-pass-review/scripts/page.py:242-249

Corroborated by sec-1 — “Compare pass provenance before formatting its display label”

render_scope decides whether the passes were peers by comparing requested_tier()'s display strings, even though the contract is the pair (requested_model, requested_effort). That formatting is not injective: a security envelope carrying only requested_model: "high effort" and a quality envelope carrying only requested_effort: "high" both become high effort. launch returns an exit code, or None when the binary could not be executed at all. sec-3

The probe for interop variables also accepts an empty value

Security & correctnesslowmedium confidence
.agents/skills/two-pass-review/scripts/render.py:61-72

is_wsl treats the presence of WSL_INTEROP or WSL_DISTRO_NAME in os.environ as conclusive, but an exported-and-empty variable is present. A user shell that clears one of these — some login managers do — puts the renderer onto the Windows ladder on a host with no Windows to reach, and every rung then fails in turn before the Linux fallback runs. Test the value, not the key.

sec-4

markdown_subset should refuse scheme-relative URLs too

Security & correctnesslow
.agents/skills/two-pass-review/scripts/markdown_subset.py:88-104

The link filter refuses javascript:, data: and vbscript: by scheme. A //evil.example/x href carries no scheme at all and survives the check, and over file:// it resolves to file://evil.example/x — harmless in practice, but the same string forwarded into a page served over HTTP is a live off-origin fetch. The report is explicitly designed to be forwarded by email, so the second case is not hypothetical.
